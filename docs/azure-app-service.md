# Azure App Service (Linux, Code deployment)

The Azure-generated GitHub workflow installs dependencies with `pip install -r requirements.txt`. This repository supplies that file, generated from the committed `uv.lock`.

## Required settings

For the existing `product-service` app in resource group `CST8915-Lab3`:

| Setting | Value |
| --- | --- |
| Runtime stack | Python 3.14 |
| Startup Command | `sh startup.sh` |
| Environment variable `SCM_DO_BUILD_DURING_DEPLOYMENT` | `1` |

The startup command is under **Settings > Configuration > General settings** in the portal (some portal layouts call this **Stack settings**). Set the Startup Command to `sh startup.sh` and save it.

The startup script adds `src/` to Python's import path and starts `python -m product_service`. It defaults to `HOST=0.0.0.0` and `PORT=8000` for App Service. An injected environment variable takes precedence. Ordinary local runs retain the application's original port 3030.

Keep the built-in image's port and the application's port aligned. For this app, leave `PORT` unset or set it to `8000`. The custom-container setting `WEBSITES_PORT` is not needed for this Code deployment.

The workflow generated by Azure remains in `.github/workflows/main_product-service.yml`. Its existing Azure identity and secret references are preserved. A push to `main` triggers its build and deploy jobs. With build automation enabled, Azure installs Linux dependencies rather than relying on a Windows virtual environment.

## Verify the deployment

The build job and deploy job must both finish successfully. Then request:

```text
https://product-service-h8gsc5gyeaa9aqaq.mexicocentral-01.azurewebsites.net/products
https://product-service-h8gsc5gyeaa9aqaq.mexicocentral-01.azurewebsites.net/health/live
```

`/products` returns the original three products directly from Python code. The application's root `/` is not an API route; use `/products` or `/docs` when checking the service.

If GitHub's build fails, inspect the failing Actions step. If deployment succeeds but the app does not start, inspect **Monitoring > Log stream**. Azure's default welcome page means the intended application is not running.

## Refresh the dependency export

After an intentional dependency update:

```powershell
uv lock
uv export --locked --no-dev --no-emit-project --format requirements-txt --output-file requirements.txt
```

Commit `pyproject.toml`, `uv.lock`, and `requirements.txt` together. The export contains exact runtime dependencies and hashes. The project's own Python package is imported from `src/` by the startup script.

References: [Azure Python build and startup configuration](https://learn.microsoft.com/en-us/azure/app-service/configure-language-python), [Azure Python quickstart](https://learn.microsoft.com/en-us/azure/app-service/quickstart-python).
